## Phase 1 — Web fundamentals

Weeks 1–2

Learn and practise:

- HTML semantics, forms and validation.
- CSS box model, Flexbox, Grid and responsive layouts.
- JavaScript functions, arrays, objects, DOM events and asynchronous requests.
- Git basics: commits, branches and GitHub.

Build: A student management interface that lets you add, search, edit and delete records in the browser.

Free resources: [MDN Web Docs](https://developer.mozilla.org/en-US/docs/Learn_web_development) · [freeCodeCamp](https://www.freecodecamp.org/learn/)

Move on when you can build a basic interactive page without copying a tutorial line by line.

## Phase 2 — Python and backend development

Weeks 3–5

Week 3: Refresh Python functions, collections, classes, modules, exceptions and debugging.

Week 4: Learn HTTP requests and responses, JSON, REST conventions, status codes and API design.

Week 5: Consolidate Django and Django REST Framework—models, migrations, serializers, views, routing, validation and permissions.

Build: A student API that supports creating, reading, updating and deleting records.

Resources: [Python tutorial](https://docs.python.org/3/tutorial/) · [Django tutorial](https://docs.djangoproject.com/en/stable/intro/) · [DRF quickstart](https://www.django-rest-framework.org/tutorial/quickstart/)

## Phase 3 — Databases and data modeling

Weeks 6–7

Focus on PostgreSQL:

- Tables, primary and foreign keys.
- One-to-many and many-to-many relationships.
- SQL queries, JOINs and constraints.
- Transactions, indexes and basic normalization.
- Database migrations and query debugging.

Build: A database for students, classes and attendance.

Learn to sketch the relationships before writing the models. Skip MongoDB for now; you don't need a second database to become productive.

Resource: [PostgreSQL tutorial](https://www.postgresql.org/docs/current/tutorial.html)

## Phase 4 — Full-stack development

Weeks 8–11

Use your EduManage project as your main learning environment.

1. Connect the JavaScript frontend to the Django API.
2. Persist student records in PostgreSQL.
3. Add authentication and role-based permissions.
4. Add classes and attendance.
5. Handle invalid input, failed requests and access restrictions.

Your target is one complete workflow that works from browser to database and back. Don't rush to build every module.

## Phase 5 — Testing, debugging and security

Weeks 12–13

Learn:

- Django unit and API tests.
- Testing valid and invalid inputs.
- Authentication and authorization checks.
- Debugging tracebacks and browser network requests.
- Environment variables and secret management.
- Basic protection against common web vulnerabilities.

Build: An automated test suite that catches broken student registration, unauthorized access and invalid data.

Resource: [Django testing documentation](https://docs.djangoproject.com/en/stable/topics/testing/)

## Phase 6 — Deployment and income

Weeks 14–16

Learn:

- Git branches and pull requests.
- Environment configuration and production settings.
- Deploying a Django application with a managed or hosted PostgreSQL database.
- Logs, errors, backups and basic maintenance.
- Writing a clear README with screenshots and setup instructions.

Deploy EduManage and then pursue practical opportunities: small business workflows, backend tasks, internships, junior developer positions or carefully scoped freelance projects.

Your project is evidence of ability, not a guarantee of income. Pair it with outreach and applications.

## How to use AI throughout the roadmap

Use this cycle for every feature:

1. Plan: Write down the requirements and expected behaviour.
2. Attempt: Design the solution and implement what you can.
3. Ask: Use AI to explain concepts, diagnose errors or review a small change.
4. Test: Check normal cases, edge cases, permissions and failures.
5. Explain: Make sure you can explain the implementation yourself.

Don't ban AI completely, and don't let it build entire systems you cannot understand.
